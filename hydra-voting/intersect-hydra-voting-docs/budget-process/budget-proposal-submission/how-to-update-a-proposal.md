# ✏️ How to Update a Proposal

## When can you update a proposal?

You can update your proposal:

* After initial submission
* During the **feedback and iteration phase**
* Before Hydra voting begins

{% hint style="danger" %}
Once Hydra voting starts, proposals are **locked** and cannot be changed
{% endhint %}

***

{% stepper %}
{% step %}
### Step 1: Go to your Dashboard



1. Click **My Dashboard** in the top navigation
2. Navigate to **My Proposals**

Here you will see:

* All your proposals
* Their status:
  * **Draft**
  * **Live** (submitted and visible)

<figure><img src="../../.gitbook/assets/image (5).png" alt=""><figcaption></figcaption></figure>
{% endstep %}

{% step %}
### Step 2: Select the proposal to edit

Find the proposal you want to update.

In the **Actions** column, click:

✏️ **Edit**
{% endstep %}

{% step %}
### Step 3: Edit your proposal

You will enter the same form used for submission.

You can update any section:

1. Proposal Overview
2. Alignment to Strategy Framework
3. Proposer
4. Proposal Details
5. Budget Administration
6. Budget Summary
7. Other Supporting Info
8. Treasury Donation Verification _(already provided)_
9. Legal Declarations _(must be reconfirmed)_

{% hint style="info" %}
### Important: Editing behaviour

When editing a **live proposal**:

* ❌ Changes are **not saved automatically**
* ❌ There is **no Save option**
* ✅ Changes are only applied when you **re-submit the proposal**

👉 This means:

* If you leave the page without re-submitting, your changes will be lost
{% endhint %}
{% endstep %}

{% step %}
### Step 4: Preview your updated proposal

Before submitting:

* Click **Preview Proposal**

This allows you to review your updated version before re-submitting.

<figure><img src="../../.gitbook/assets/image (6).png" alt=""><figcaption></figcaption></figure>
{% endstep %}

{% step %}
### Step 5: Re-submit your proposal

When ready:

1. Click **Re-Submit Proposal**
2. Confirm required fields:

* Legal declarations
* Submitter information (name, email, role)

👉 Legal declarations must be confirmed **every time you re-submit**
{% endstep %}
{% endstepper %}

***

## Versioning

Each time you update and re-submit:

* A **new version** of your proposal is created
* Previous versions remain visible
* Changes between versions can be tracked

👉 This ensures full transparency for DReps and reviewers

#### Viewing proposal versions

You can view previous versions of your proposal:

* Click **View previous versions** on the proposal page
* A **revision history panel** will open
* Select any version to view it

<figure><img src="../../.gitbook/assets/image (7).png" alt=""><figcaption></figcaption></figure>

In the revision history:

* The **current version** is clearly marked
* Previous versions are listed with timestamps
* Changes between versions are summarized

👉 This allows DReps and reviewers to understand how the proposal has evolved over time

***

## What happens after re-submission

* Your updated version becomes the **current active version**
* Previous versions remain visible
* Feedback can continue on the updated proposal
